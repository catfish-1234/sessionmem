# Security policy

## Supported versions

Security fixes are provided for the latest published stable release of
sessionmem (currently 1.3.0). Older releases and prereleases are not supported;
upgrade to the latest stable release before checking whether an issue persists.
The main branch receives fixes for the next release but is not a supported
published version.

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/catfish-1234/sessionmem/security/advisories/new)
to open a private security advisory. You need a GitHub account. Reports stay
private while maintainers investigate and coordinate a fix with the reporter.
Do not disclose vulnerabilities in public issues, pull requests, or discussions.

Include the affected version, operating system and Node.js version, reproduction
steps or a minimal proof of concept, expected impact, and any suggested mitigation.
Use synthetic data: do not include real API keys, private session transcripts,
production memory databases, or other sensitive information.

## Response expectations

Maintainers aim to acknowledge reports within 7 calendar days and provide an
initial assessment within 14 calendar days. These are best-effort targets for a
community-maintained project, not guaranteed service levels. If you have not
heard back after 7 days, follow up in the same private advisory.

For confirmed vulnerabilities, maintainers coordinate remediation, disclosure
timing, and reporter credit in the private advisory. Fix timing depends on
severity and complexity; maintainers will share progress and available
workarounds there. Keep details private until coordinated disclosure.
